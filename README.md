# CRM 客户管理系统 · 高保真交互 Demo

一个用于课堂作业展示的银行对公 CRM 系统前端 Demo，覆盖「线索 → 分配 → 跟进 → 客户 → 开户申请 → 合规审核 → 审批 → 开户任务结果」的完整业务流程，并叠加「概览 / 数据看板」与「业绩分配与薪酬管理」两个经营分析模块。所有操作真实改变前端数据，并持久化到浏览器本地存储（刷新后保留）。

## 一、环境要求与启动

- Node.js ≥ 18（建议 20+），npm ≥ 9
- 现代桌面浏览器（Chrome / Edge / Safari），优先在 1440px 左右宽度下查看

```bash
npm install        # 安装依赖（首次）
npm run dev        # 启动开发服务器，默认 http://localhost:5173
npm run build      # 类型检查 + 生产构建
npm run preview    # 预览生产构建
```

> 项目未接入任何真实银行系统 / 外部 API / 真实客户数据，全部为本地 Mock 数据 + localStorage。

## 二、技术栈

- React 18 + TypeScript + Vite 5
- Ant Design 5（企业级组件库）
- Zustand（状态管理，`persist` 中间件做 localStorage 持久化）
- React Router 6（路由）
- Recharts 3（数据看板可视化图表）
- dayjs（日期处理）

## 三、页面结构与路由

统一使用左侧边导航 + 顶部标题栏（含面包屑、演示角色切换器、重置数据按钮）。

| 页面 | 路由 | 说明 |
| --- | --- | --- |
| 概览 / 数据看板 | `/dashboard` | 线索转化漏斗、跟进频次、开户完成率、业绩目标完成度等聚合可视化（默认首页） |
| P01 线索管理 | `/leads` | 指标卡片、搜索/筛选、线索列表、新增/编辑/详情、行内分配弹窗 |
| P02 线索分配 | `/assign` | 待分配列表、多选、客户经理选择、二次确认分配 |
| P03 线索跟进与客户详情 | `/leads/:id`、`/customers/:id` | 基本信息 / 跟进记录 / 业务历史 三页签 |
| P03 跟进管理 | `/followups` | 跟进记录总览、新增跟进记录、对象类型/关键字/时间筛选 |
| P04 客户管理 | `/customers` | 客户搜索、类型/状态筛选、开户情况汇总、新增自拓客户、行内创建开户申请 |

## 四、角色与权限（演示用角色模拟）

顶部右侧「角色切换器」用于切换身份，**仅为演示用角色模拟，不是真实身份认证**。可选身份：

- 客户经理：张伟 / 李娜 / 王强 —— 创建、编辑、提交**本人**名下的开户申请；管理线索与跟进
- 合规审核人员：陈静 —— 审核客户资料（通过 / 驳回补充资料）
- 客户主管：赵磊 —— 开户审批（通过 / 驳回）

权限要点：

- 开户申请只能由「客户经理」创建，且仅能编辑/提交**本人创建**且处于「待提交 / 需补充资料」的申请
- 合规审核操作仅「合规审核人员」可见；审批操作仅「客户主管」可见，其他角色在对应页签会看到无权限提示
- **未通过合规审核的申请不会进入审批环节**，无法被直接审批通过（审批列表仅含 `待审批` 状态，且审批前再次校验合规结论）

## 五、数据模型与状态机

实体：`用户/角色`、`线索 Lead`、`跟进记录 FollowUp`、`客户 Customer`、`开户申请 Application`（含证明材料、合规审核、审批、历史记录、业绩额）、`业绩目标 PerformanceTarget`、`提成规则 CommissionRule`。

编号规则：线索 `LX000001`、客户 `CUS000001`、开户申请 `KH000001`、跟进 `FU000001`、业绩目标 `MB000001`（自增）。

线索状态**由流程自动流转**：新增即「待分配」→ 分配负责人后「跟进中」→ 转为客户后「已转化」，用户不可手动改状态。

开户申请状态机：

```
待提交(draft) ──提交──▶ 待审核(pending_review) ──合规通过──▶ 待审批(pending_approval) ──审批通过──▶ 已通过(approved)
     ▲                        │ 合规驳回                                              │ 审批驳回
     │                        └──▶ 需补充资料(need_supplement) ──重新提交──▶ (回到待审核)   └──▶ 已驳回(rejected，终态)
     └────保存草稿（可反复编辑）
```

「开户任务与结果」（P05 内页签）的每一行都由开户申请**派生**；客户「是否已开户」由名下申请是否出现 `已通过(approved)` 派生；看板与薪酬模块的实际回款由「已开户申请的业绩额合计」派生，保证与前面各页数据一致、不产生互相矛盾的数据。

业绩目标审批流：`草稿(draft) ──提交──▶ 待审批(pending) ──销售确认 → 部门主管审批 → 财务确认──▶ 已通过(approved)`，任一环节可驳回（`rejected`）。

## 六、字段设计假设

- 开户申请表单分为四组：**客户主体信息**（关联客户、客户名称、主体类型、法定名称、统一社会信用代码、法定代表人、注册地址）、**联系人信息**（联系人、电话、邮箱）、**证件及证明材料**、**开户类型及相关申请信息**（开户类型、开户网点、开户金额/业绩额、币种、备注）。选择「关联客户」后自动带出该客户名称、主体类型、联系人、电话等，避免重复录入。
- 证明材料（默认 6 项）：营业执照、法定代表人身份证、受益所有人信息采集表为**必填**；开户许可证、公司章程、经营场所证明为选填。**提交时校验：必填字段 + 所有必填材料均已上传，否则无法提交**；保存草稿不强制完整。
- 「上传附件」为演示占位：点击即标记为「已上传」，不真实读取/上传文件。
- 线索新增遵循「最简原则」：仅录入名称、来源、联系人、电话、意向；编号自动生成、负责人与状态由分配流程自动维护，手机号做 11 位正则校验。
- 客户列表的「开户情况」为派生汇总（已开户 / 未开户），不在客户主表写死一对一的开户审核状态。
- 所有关联字段（跟进记录↔线索/客户、开户申请↔客户）均以唯一编号/ID 关联，源头修改后相关展示自动同步。

## 七、演示流程建议

### 快速体验既有数据
1. 打开后默认进入 **概览 / 数据看板**，查看线索转化漏斗、开户完成率与业绩完成度；可在右侧切换角色查看各角色视角。
2. **P05 工作台 → 客户资料合规审核**：切换到「合规审核人员 · 陈静」，对「上海星辉文化传媒」的申请执行「审核通过」或「驳回补充资料」（驳回需填原因）。
3. **P05 工作台 → 开户审批**：切换到「客户主管 · 赵磊」，对「杭州云图科技」的待审批申请执行「审批通过/驳回」。
4. **P05 工作台 → 开户任务与结果**：观察上述操作后任务状态与最终结果同步变化；对「需补充资料」的任务点击「补充资料」可回到表单。
5. **业绩分配与薪酬管理**：查看目标审批流（销售确认 → 部门主管 → 财务），调整提成规则后观察完成率与提成金额自动重算。

### 走一遍完整开户流程（从零开始）
1. **P01 线索管理**：点「新增线索」填写必填字段（名称/来源/联系人/电话等）保存，列表出现新记录（状态自动为「待分配」）。
2. **P01 线索管理 → 分配**：在行内点「分配」弹窗，选择客户经理确认 → 负责人与状态自动变为「跟进中」（也可到 P02 批量分配）。
3. **P03 线索详情**：点该线索「详情」→「跟进记录」页签「新增跟进记录」→ 时间线更新；点「转为客户」生成客户档案。
4. **P04 客户管理 / 客户详情 → 创建开户申请**：行内点「创建开户申请」弹出表单并自动带入客户资料，选择「关联客户」自动带出联系人等信息，填写开户金额，点「上传附件」补齐全三项必填材料，点「提交申请」（可先用「保存草稿」或故意缺材料，验证必填/材料校验拦截）。
5. **P05 → 客户资料合规审核**：切换「合规审核人员 · 陈静」，对刚提交的申请「审核通过」（或「驳回补充资料」验证必填原因）。
6. **P05 → 开户审批**：切换「客户主管 · 赵磊」，「审批通过」完成。
7. **P05 工作台 → 开户任务与结果**：该申请已显示为「已完成 / 开户成功」，点「详情」可查看完整时间线、审核意见与最终结果；回到看板可见开户完成率、业绩完成度同步更新。

### 验证关键规则
- 必填字段与材料完整性校验：缺任一必填项或必填材料无法「提交申请」。
- 合规驳回必须填写原因；驳回后可在任务页「补充资料」重新提交。
- 未通过合规审核的申请不会出现在「开户审批」页签，无法被直接审批通过。
- 不同角色看到的操作按钮不同（新建/编辑仅客户经理、审核仅合规人员、审批仅主管）。

## 八、Demo 假设与边界说明

1. 需求文档未作为独立文件提供，本实现以任务描述中的完整规格为准。
2. 线索分配未限定特定角色，Demo 中任意角色均可进入 P02 操作（简化处理）。
3. 附件上传为占位模拟；时间默认取当前时间，可手动修改。
4. 数据存于浏览器 `localStorage`，可通过顶部「重置演示数据」按钮一键恢复初始种子数据。
5. 演示种子数据覆盖：正常完成流程、待审核、待审批、驳回补充、草稿待提交、已驳回/已流失等状态。
